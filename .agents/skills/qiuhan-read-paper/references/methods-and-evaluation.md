## 一、如何把长方法拆成可运行结构

### 1. 摘要提供根，章节提供树，段落提供微结构

课程用 DeepAID 示范：根是“解释并改进安全异常检测”，第 4 节和第 5 节分别展开解释与蒸馏。解释又分统一问题、表格解释器、时序解释器、图解释器。继续向下看，每个子模块都有目标、挑战、核心求解，以及初始化、效率、简洁性等补充问题。不要把树状结构压平为一个技术名词列表。（课程方法：L02-P038–P040，L03-P006–P013。）

操作时先定位每层在回答哪个问题：

| 层级 | 问题 | 需要读出的内容 |
|---|---|---|
| 全文核心 | 为什么做这项工作 | 研究问题、核心想法与主张 |
| 方法主分支 | 为实现想法需要哪些主要能力 | 模块职责及它们之间的关系 |
| 子模块 | 此部分怎样实现其职责 | 目标、挑战、关键动作与条件 |
| 技术细节 | 关键动作为什么可行 | 公式、算法、数据结构及分析 |
| 改进与讨论 | 在什么边界下更好或更差 | 初始化、鲁棒性、代价、例外 |

这是课程微结构的运行化整理。标题可以暗示结构，但必须用正文核对：标题写“优化”并不证明已经数学优化，角色名写 Agent 也不自动证明它是独立模型或进程。

### 2. 分清主线、场景差异与旁支改进

第三讲将表格解释器作为较完整案例，后续时序与图数据部分更多补充差异。读后续场景时先继承共享框架，再核对新增条件，不能假设每个场景都独立从零开始。图数据也可能先分类、再针对类别讨论。Distiller 的设计、例子、与其他机制比较和降低误报分别承担不同作用。（课程方法：L03-P010–P013 及备注。）

识别旁支改进时问：没有它是否还完成基本任务？它是在解决核心困难，还是提高速度、紧凑度、稳定性或可用性？“可选改进”要以文中实际依赖为准，不仅依照段落位置判断。后置讨论可能解释为何这样设计，也可能响应评审，但没有公开版本证据时，不能断言“这一段一定是审稿人要求加的”。（课程原则：L03-P013、P030；录音解释：L03 20:25–27:56，未逐段核听。）

### 3. 每个组件至少讲清一条真实交接

运行化整理：沿同一输入追踪“输入从哪里来 → 执行者做什么 → 产生什么中间产物 → 下游怎样使用”。例如对于一个解释器，不只说“它输出解释”，还要核对解释究竟是特征索引、差值、参考样本、规则还是文本；下游将它用于显示、决策、蒸馏还是更新。原文没说具体格式就写“未说明”，不为方便讲解虚构真实 schema。

必要时使用紧凑表格：

| 原文模块 | 输入和来源 | 核心操作/约束 | 输出及消费者 |
|---|---|---|---|
| 模块 A | 原文给定 | 原文可定位的动作 | 原文实际交接 |
| 模块 B | A 的结果及其他输入 | 原文具体计算/选择 | 后续用途 |

这张表不能靠常识补满。没有足够原文时，保留空缺和定位请求。尤其区分用户规格、系统状态、模型参数、临时缓存、生成候选和最终结果，不统称“记忆”。

### 4. 公式先解释目的，再解释计算

先说明符号所表示的对象、希望控制或优化的量、约束排除了什么、输出将进入哪一步，再展开推导。若用户只需理解研究想法，不把每个公式都演算；若要复现或判断理论主张，必须读清假设、变量维度、优化对象、近似和停止条件。数学表达复杂不自动说明贡献强，简单也不说明没有新意。（课程方法：L03-P009–P014、P040；运行化整理：符号与执行映射。）

涉及训练与推理时分别梳理。标签/偏好/奖励从何来、训练怎样改变参数、使用时读什么输入，不能混讲。“生成器会学习这个反馈”需要对应参数更新或明确的状态复用，不能因为下一轮看到文字就称为训练。

## 二、从示例走到真实机制

### 1. 先看 toy example，再回正文

课程建议优先找示例，利用图中具体步骤快速理解方法，再读详细机制。第三讲备注同时提醒 toy example 可能不完整或误导。因此先用例子建立直觉，再逐项核对真实问题中的规模、输入类型、约束、失败路径和代价。（课程方法：L02-P040，L03-P014 及备注。）

真正讲例子时，至少展示一个中间状态；例如“输入样本 → 解释目标 → 求解后的变化 → 如何被 Distiller 使用”。若原例没有完整中间数据，不用凭空给出数字冒充原文；可以另造明确标注的教学例子，并说明它保留什么、简化什么。教学例子中数字应单独核算，不以硬编码预期值自证。

### 2. 流程图不是装饰

先看原图、图注和正文；按图中标签和箭头讲解，同时辨认输入、处理、输出、示例及反馈。左边/上面的位置不必然表示先执行，编号也可能只是展示顺序。先说清执行者和判断依据，再解释每个分支。模型作决定、程序规则执行和用户已指定是不同控制方式。（课程原则：L03-P013–P014；录音辅助：L03 29:41–31:57；具体图区分为运行化整理。）

若需要自绘教学图，标清已核验连接与原文未说明处；不要把不明路由画成确定的分类器。用户只要求普通阅读时，优先在聊天里讲或用可读图示，不自动开发网站、课程或独立图文件。

### 3. 循环、选优与停止尤其要核清

对于迭代、搜索和反馈类方法，追踪：谁提出候选，谁评价，反馈给谁，改的是数据、提示、程序、规格、局部结果还是模型参数，哪些已接受状态被保留。区分一次多候选选优与根据反馈改动的多轮搜索。原文不交代终点时不得补出“直到全部合格”；达到最高分也不自动代表满足全部要求。（运行化整理，服务课程“逻辑链有无断裂”的检查：L03-P030。）

若最后返回历史最佳而非最新候选，明确说明；若有回退，说明实际恢复的对象。生成结构合法、代码能运行、图像可解码和语义有效分别需要证据，不得因为中间表示通过验证就跳到下游成功结论。

## 三、方法优势与工程实现

### 1. 不只问“做了什么”，还问“为何值得这样做”

课程录音将方法部分的阅读提升到：它是否必要？真的需要这个设计吗？好处在哪里？能否用更简单的办法做到？设计优势不必都化为某个性能数字，例如抽象复杂性、可理解性、开发便利等也可能重要。但这种优势要有论证或适当证据，不能依靠漂亮措辞代替。（课件基础：L03-P013、P030、P040；录音辅助：L03 25:15–27:56，未逐段核听。）

评价时分开“设计意图”“逻辑分析支持”“实验结果支持”和“仍待验证”。没有实验不等于所有设计讨论无价值；有实验也不等于理论机制已经被因果证明。应把结论限制在证据实际检验到的层次。

### 2. 设计与实现是两件事

第三讲要求检查 full-fledged implementation、prototype 和 simulation，以及实现如何映射方法。原型可以检验核心机制，但不自动代表生产系统；仿真可以检验受控假设，但需要说明模型真实性；真实部署也需核查部署规模和条件。（课程方法：L03-P016 备注、P018 备注、P021。）

阅读实现时逐项核对：

- 哪些核心模块真实实现，哪些只讨论或模拟；
- 实际软件、硬件和外部环境是什么；
- 工程挑战与设计挑战有何不同；
- 受环境限制的替代实现是否仍检验原主张；
- 实现规模能支撑怎样的泛化；
- 代码是否可得，是否对应本文版本。

课程录音强调有限资源可能使真实部署困难，需退而采用原型或仿真；这不能简单判成“仿真没有价值”，而要问何种机制保真、何种结论仍未知。（辅助：L03 01:01:13–01:06:44，未逐段核听。）

## 四、先读实验设置，再读性能数字

### 1. 设置是可信度的前提

第三讲把实验设置的重要性说得很明确：它决定评价是否可信。先弄清怎么做，再看提升多少。不要用“提升 100 倍”掩盖弱基线、不同硬件、数据不匹配或定义不同。实验设置正文很短时，检查附录，不能未经搜索就认定作者未报告。（课程方法：L03-P016–P023 及备注。）

### 2. 数据：代表性、多样性与规模分别核对

课程要求关注数据是什么、真实与否、代表性、规模是否足够、伦理、公开、可复现和能否用于自己的研究。（L03-P020。）

运行时问：

1. **来源与生成机制**：真实采集、公开历史数据、合成、仿真还是模型生成？数据怎样形成，哪些偏差可能由生成机制带来？
2. **覆盖范围**：是否覆盖论文声明的任务、数据类型、用户、环境、异常与边界？三个类型的方法只测一个类型，应说明验证范围受限。
3. **数量与独立性**：样本、时间跨度、场景/主体数分别多大；大体积不等于多样性，多次相似采样不等于独立覆盖。
4. **协议**：训练、验证、测试怎样划分；是否存在信息泄漏、重复或不合理挑选？这些是课程原则迁移到现代实验的检查。
5. **伦理与复用**：隐私、同意、许可、敏感漏洞或群体偏见怎样处理；没有公开不等于虚假，公开也不自动保证复现成功。

课程录音明确讨论“大规模不必然比多样性更重要”、合成数据并非天然无价值、私有数据不必然是假数据，以及脱敏可能影响复现等权衡。对这些点不采用一刀切判断。（辅助：L03 50:23–01:01:13，未逐段核听；核心清单可由课件直接支持。）

### 3. 环境、参数与程序

记录每项实验的软件、硬件、外部条件与执行步骤。参数不只抄一个值，还问为什么选、怎样调、是否匹配真实场景、不同配置是否评估。一个全局设置可能不足以描述各个实验，需核对小节开头、图注和附录中的局部条件。（课程方法：L03-P021–P022；辅助：L03 01:07:16–01:09:27。）

无法知道关键配置时，写“论文未报告/本轮未找到”，并说明它影响复现、可信性还是结果解释，不一律上升到“不可信”。如果资料仅是摘录，就写“所给摘录未包含”，不把未看到当成全文缺失。

### 4. 基线与公平比较

课程要求明确与谁比较、为何合理以及如何比较。优先核对研究当时与问题相匹配的强方案和相关 SOTA；经典方案可提供定位，但不能仅用多年以前的弱方案支撑对当代最好方法的领先。（课程方法：L03-P016 备注、P022；辅助：L03 01:08:15–01:09:27。）

运行化整理的公平性检查包括：同数据划分、同指标定义、同硬件或合理归一、同调参机会、候选/采样/搜索预算、外部工具和训练数据、是否使用官方实现与推荐配置。不能把多次选优相对一次生成的全部收益归给编排本身；也不能未经比较便断言预算解释了全部收益。准确写出论文实际控制了什么、没有说明什么。

### 5. 指标：名称、分母与覆盖都需要

课程的五问是评什么、为什么、能否覆盖各方面、如何计算、有无遗漏。（L03-P023。）运行时至少核对对象、计算公式、单位、方向、汇总方式和适用假设。平均分、成功率、相对提升、百分点、胜平负汇总和统计显著性不是同一个东西。涉及数值计算交给工具核算，报告基准值与分母。

例如 60% 到 72% 是提高 12 个百分点、相对提高 20%；教学例子应标注为示意。准确率可能掩盖类别不平衡，平均延迟可能掩盖尾部开销；这些是基于课程“有没有缺失指标”的迁移检查，不冒称课件逐字示例。

## 五、四类证据分别说明什么

### 1. 整体端到端评价

把整个方案视为整体，看它是否达到预先承诺的目标，核对指标是否呼应方法设计。DeepAID 示例列出 fidelity–conciseness、stability、noise/attack robustness 和 efficiency，并要求呼应设计中的目标。其他论文不能照搬这些指标，必须按本篇主张选择。（课程方法：L03-P024–P025。）

读每组结果遵循“怎样测 → 观察到什么 → 为何可能这样 → 新的洞见和经验”。作者解释是一个论证环节，要检查是否有对照、分析或其他证据，不能把 post hoc 解释直接当因果结论。失败案例、性能反转和适用边界也属于重要结果。

### 2. 微基准与消融

课程要求理解各组件：测什么组件、用什么指标、怎样运行、结果和原因、有没有未评估组件。整体效果好不代表每个模块都必要；微基准可暴露无效、冗余或代价过高的部分。（课程方法：L03-P026；辅助：L03 01:14:22–01:15:15。）

微基准与消融并非严格同义：微基准可单独测组件的行为和开销；消融通常在明确的完整配置中删去/替换组件，再观察变化。必须说明改动前后保留了什么、其他条件是否相同、是否存在交互作用。一个组件的提升支持其在当前设置下有用，不保证在所有设置下都必要。

尤其注意课件 P026 明确说示范论文没有对应单列消融部分，而该类分析在其他论文中常见。不能把教学补充说成 DeepAID 已经完成的实验。

### 3. 案例研究

案例展示具体使用场景、功能特征与经验，可以容纳不易量化的优势。用例要读真实输入、操作过程、结果与证据；用户反馈要看调查对象与方法。一个成功例子说明存在这种用法，不自动说明平均成功率、可扩展性或真实部署收益。（课程方法：L03-P027；辅助：L03 38:12–39:39。）

与整体评价互相补充：统计结果给出覆盖和分布，案例帮助理解如何发生。不要让鲜明故事遮住选择偏差，也不因没有大样本就抹掉案例的机制说明价值。

### 4. 附录补充实验

先定位附录是否补充关键设置、推导、额外数据或敏感性分析。若核心可验证信息在附录中，阅读评价时应按目标补读；但评价论文表达时可以指出正文是否足以理解主论证。附录多不代表证据强，附录少也不是自动缺陷。（课程方法：L03-P015 备注、P016、P018；后续写作课程会区分正文必要内容与补充材料。）

## 六、将主张、实验与结论对齐

运行化整理：对核心主张建立一行证据链：

> 主张 C → 需要什么观察才能支持 C → 文中实验实际测了什么 → 结果 → 可支持的结论 → 仍未覆盖的条件。

例如论文声称“在三类数据上解释并改进”，需要分别核对解释和改进的验证，不因解释器覆盖三类输入就推断 Distiller 也覆盖三类。作者概括、方法支持范围、实现覆盖和实验覆盖应分别记录。（课程示例基础：L01-P038，L03-P005–P006、P020–P026。）

把缺口分成四类：

- **逻辑缺口**：结论不能由给定前提推出。
- **证据缺口**：主张可能合理，但本轮材料没有直接验证。
- **描述缺口**：关键实现或设置不清，阻碍判断。
- **范围限制**：作者明确限定的应用条件，未必推翻其范围内的结果。

提出更强验证时注明“建议补做”，不要暗示论文已做。例如相同预算的结构化修订与自由文本修订比较，是建议的鉴别性实验；原文没报告等预算控制，不等于已证实结果全是预算带来的。

## 七、安全/系统分支与跨领域迁移

课程处于网络空间安全语境。涉及攻防主张时，阅读威胁模型：攻击者/防御者目标、能力、知识、访问和限制，以及攻防交互。把实验覆盖映射到这些假设；放宽攻击能力后结论是否仍成立，需要专门证据。普通非安全论文不强加攻击者模型。（课程背景：L01-P005、P024–P026；具体操作为通用运行化整理，写作课程有更完整的威胁模型指南。）

系统论文区分设计可行性、实现完整性、实际部署和性能收益。算法/理论论文改用假设、证明和计算实验之间的对应；观察性研究改用研究设计、混杂、偏差和测量；综述论文检查检索范围、选择标准、分类与综合，而不要求一定存在“新系统”。这些是跨领域迁移，不代表老师对所有研究范式逐项授课。

当前课程资料覆盖不了某学科的特殊统计、伦理或报告准则时，按任务调用一手标准或领域方法，不用课程一般原则冒充全面专业验收。用户要求具体结论时先明确证据能到哪里，再提供有用分析，而非只输出免责声明。

## 八、完成前检查

1. 是否能把每个关键模块接到研究问题和下游用途？
2. 是否区分设计意图、真实实现、实验测量和作者解释？
3. 是否实际看过关键图表、图注、设置和必要附录？
4. 数据、环境、参数、基线、指标与预算能否支持比较？
5. 总体、组件和案例各自支持什么，不能推出什么？
6. 是否记录反常结果、局限和未覆盖组合？
7. 结论强度是否与本轮可得资料一致，数字计算是否正确？
8. 是否把建议、迁移和教学例子清楚区分于论文事实？

通过这些检查表示分析得到相称支持，不能据此宣称论文所有结果已复现、理论已独立证明或用户已经掌握。
