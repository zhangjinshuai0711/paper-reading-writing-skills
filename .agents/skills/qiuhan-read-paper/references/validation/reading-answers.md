## R1：课程案例 DeepAID

### 题面

仅依据包内 DeepAID 课件提取问题→idea→Interpreter/Distiller 输入输出→实验已知与未知；不得假装有原论文全文，核查 SHAP 和消融。

### 实际回答

本轮依据课程课页及其中恢复的论文截图，尚未读取一份完整、独立的 DeepAID 原论文与完整附录。下面可以还原它的核心机制和课件能直接支持的边界，不能据此宣称实验已经独立复现。

一句话概括：DeepAID 针对安全无监督深度异常检测中“发现异常后难理解、难信任和难改进”的问题，先为异常寻找有约束的解释，再把解释及分析人员反馈转成可更新的判断机制，让解释服务于系统使用和改进。

论证链为：安全异常检测使用无监督深度模型→检测结果缺乏可解释性→作者认为面向监督模型或非安全场景的解释办法不能直接满足此场景→按安全需求构造解释优化→用 Interpreter 生成解释，用 Distiller 将反馈复用到相似异常→分别验证解释质量和下游应用。这里“旧解释方法不能直接适配”是作者的有条件论证，需要按其比较对象核查，不能概括为整个 SHAP 家族在任何异常检测中都无用。来源：L03-P005/P006；课件的统一表述与嵌入论文具体限制应一起理解。

| 阶段 | 输入与来源 | 核心操作 | 输出与消费者 |
|---|---|---|---|
| 原异常检测系统 | 原始数据及其深度异常模型 | 判出待分析异常 | 异常样本交给解释器；本轮不重构所有检测模型接口 |
| Interpreter，先以表格分支说明 | 异常向量及被解释模型，另有优化参数/约束 | 寻找符合正常性、有效取值范围及简洁性等要求的参考向量；据原异常与参考的差异给解释 | 参考向量与差异解释；分析人员据此理解异常；表格解释也可进入 Distiller |
| Distiller 更新 | 解释向量及分析人员反馈，构成“解释→反馈”规则 | 将解释各维映射到状态，按有效性顺序连接；更新两套有限状态机的转移 | 可用于后续测试的状态/转移关系，保留专家反馈 |
| Distiller 测试 | 新异常的解释向量、已有状态/转移 | 将解释映射成状态序列，对已有反馈计算匹配程度 | 已有反馈类别及相应匹配概率，供后续判读/处理；不是直接重新训练原深度检测器 |

Interpreter 结构覆盖表格、时序与图数据；后两类不能无条件照抄表格算法，课件专门列出异常定位、多变量时序与图类别差异。Distiller 的嵌入原文则明确目前主要面向表格，讨论段也写只实现表格版，因此不能因为解释器有三类输入就写成蒸馏同样验证三类。来源：L03-P008–P013；恢复原图 L03 image15，课件 P013；L03 image31，课件 P028。

用一个连续教学流程理解：分析员先拿到异常 A 的解释，给出“Scanning”反馈，Distiller 更新；随后测试 A 和相似异常 B，得到对已有反馈的匹配；再把 B 的更具体反馈加进去并重新测试。这对应课件 toy example 的“更新—测试—再更新—再测试”，不是一次生成后选最大值。完整机制仍要回正文核对离散化和状态次序，不能由这个小例子证明所有相似异常都能正确分类。来源：L03-P013/P014，恢复 image15 的 Figure 3/4 文字。

关于 SHAP：当前恢复截图的 related work 说某项已有工作把 SHAP 用到单个 autoencoder，作者认为该特定方案不能用于 Kitsune 的 autoencoder 集成或其他深度模型。这不支持“DeepAID 就是用 SHAP 做解释”，也不支持“DeepAID 数据集与 SHAP 数据集必然相同”。实际展示的主线是参考向量与差异解释的有约束优化。截图文字有乱码，公式和符号以原图为准；本轮没有把 AI 回答示例当作方法来源。来源：恢复 L03 image31 / P028；image12 / P010 的 Algorithm 1。

实验方面，目前能确认课件要求检查数据、实现、环境参数、指标、基线和用例；其整体解释指标包括 fidelity–conciseness、stability、对噪声/攻击的鲁棒性和效率。可以定位总体评价、理解模型决策、可调试性、人机协同、降低误报等实验/案例方向，具体每项需要看相应协议和表图。课件 P026 明写 “Not available in this paper”，故课程对微基准/消融的一般介绍不能写成 DeepAID 已完成完整组件消融。

| 主张 | 本轮材料能支持什么 | 仍不能推出什么 |
|---|---|---|
| 能解释多种数据结构 | 设计里明确三类 Interpreter，并有相关截图 | 不能只按章节名断定每种输入上所有质量指标均已充分验证 |
| 解释有助改进系统 | Distiller 的反馈机制及案例方向已展示 | 不能推断提高了所有安全系统、所有攻击条件下的实际部署收益 |
| 解释具鲁棒性 | 有具体攻击/噪声评价方向 | 讨论页限于特定优化与距离攻击，还列出其他可能失败条件，不能写“对抗鲁棒性全面保证” |
| 各组件必要 | 课程提示应检查组件证据 | 不能声称已有逐组件消融；先查原论文/附录再给更广判断 |

下一步若目标是复现：先取得对应版本全文和附录，再补清数据与划分、实际被解释模型、梯度可访问条件、归一化、目标函数、优化停止/选参、FSM 离散化与阈值、各实验基线。若目标仅是理解主线，上面的“解释→反馈→相似异常复用”已比模块名单更接近实际机制，但性能与可复现性仍未验收。

## R2：未写入示例的植物研究

### 题面

温室同一品种24株，处理/对照各12；仅一次批次，7天后处理组存活9/12，对照6/12。处理为减少浇水前预喷物质X；未报告随机化/盲法/误差或机制证据。摘要声称 X 普遍激活基因G，使田间产量提高。要求逻辑/证据评估和下一步，不硬套威胁模型。

### 实际回答

这组材料提供了一个温室存活差异的初步观察，尚不能支持摘要中的基因机制、田间增产和普遍有效三个主张。研究方向可能有用，但需要把想证明的因果链拆开。

当前真实观察是：同一品种、同一批次、给定减水条件下，预喷 X 的12株中7天后存活9株，对照12株中存活6株。对应存活比例是75%与50%，差25个百分点；相对对照的比例增幅为50%。这三个数字只是描述同一观察，不是三份独立证据，也不意味着已证明统计显著或普遍有效。

作者希望建立的链是“预喷 X→激活基因 G→提高耐旱生存→田间产量增加”。实际只测了其中一个短期终点，而且分组程序和混杂控制尚不清楚。

| 主张 | 现有证据 | 判断 |
|---|---|---|
| 此条件下处理组观察到较高存活比例 | 9/12 对 6/12 | 可以如实报告观察；效应估计不稳定程度未报告 |
| X 导致差异 | 未报告随机化、初始状态及位置等控制 | 因果解释待核；“未报告”不等于已经证实没有随机化 |
| X 激活 G，并通过 G 起作用 | 无表达/蛋白/功能干预证据 | 当前不支持；不能用存活率代替机制实验 |
| 能提高田间产量 | 无田间实验，也未测产量 | 当前不支持；存活和产量是不同终点 |
| 普遍有效 | 单一品种、单批次、一个条件 | 外推过宽，需收窄 |

建议摘要现阶段写为：“在单一品种的一批温室减水试验中，X 预处理组7天存活为9/12，对照组为6/12。该初步观察需要独立重复和更明确的分组控制验证；其作用机制及田间产量效应尚未确定。”这没有抹去潜在线索，也没有让语言超出证据。

先做能影响结论的核查：索取分组、随机化、初始株况、温室位置、浇水量、X 浓度与载体对照、存活定义和数据记录。若位置、处理与其他条件绑定，即使后续用统计检验也不能自动排除混杂。记录有多少独立批次及是否有盆/架共同环境；不要把同批24株当作24个独立环境来宣称跨环境重复。

然后分层补研究，而不一次要求所有可能实验：

1. 先重复温室存活发现：按明确分组方案控制位置/起始条件，使用合适载体对照，保留逐株与批次记录；按研究设计报告效应与不确定性。样本量和分析方法应结合领域设计确定，本轮不凭24这个数字给通用硬阈值。
2. 如果机制是核心贡献：测量与假说相关的 G 变化，再设计能区分“相关伴随”与“必要作用”的干预/对照。仅表达变化也不足以单独证明 G 是因果中介；具体实验需植物分子生物学专业设计。
3. 如果目标是田间增产：在田间条件下实际测产量，明确品种、环境、剂量及代价；在完成前保留为计划，而非摘要结果。

这项研究不需要攻击者/防御者威胁模型。这里迁移课程的是“主张—设计—证据—范围”的通用逻辑；具体植物统计和机制方法不冒充老师在课上已经逐项教授的规范。

## R3：只给标题和一句理论摘要

### 题面

只有标题 “Proof of convergence for adaptive maps” 和一句摘要“证明在紧致性和步长条件下收敛”，用户要求完整复现。

### 实际回答

现有材料不足以完整复现证明或算法，但可以先把复现任务拆清，并列出决定是否能执行的具体缺口。

现在仅知道作者声称：某个 adaptive maps 过程在紧致性与步长条件下收敛。我们不知道 map 的定义、状态空间、更新式、步长条件、收敛对象及收敛意义。因此不能补出“使用梯度下降”“步长递减且和发散/平方和收敛”“收敛到全局最优”等常见但未给定的内容；也不能因为题目有 proof 就推断证明已正确。

需要从全文中抽取的最小对象是：

| 复现环节 | 必需信息 | 缺失的后果 |
|---|---|---|
| 定义研究对象 | 空间、范数/拓扑、映射与自适应更新 | 连要计算或证明什么都无法确定 |
| 还原定理 | 全部假设、初值、步长限制、结论的量词 | 不能确认收敛范围 |
| 理解“收敛” | 迭代点、子序列、目标值或误差？何种方式？ | 不能设计验证或判定终点 |
| 核对证明 | 引理、引用定理与适用条件、关键不等式 | 不能做逻辑复核 |
| 计算性复现（若适用） | 可执行更新、实例、数值精度与停止规则 | 不能由纯存在性证明直接生成可运行代码 |

取得对应全文或定理/算法段后，我会按原文先重述定义和定理，再把证明拆为依赖链，对每一步核对引用条件是否满足，尤其“紧致性”究竟被用于取收敛子列、存在性还是一致控制。这里列的是可能的用途检查，不能预先认定作者采用其中哪一种。

若论文给出可执行迭代，再在明确满足假设的实例上实现并检查收敛行为；数值成功只能支持该实例，不能代替一般证明。若论文给的是纯理论存在性结果，复现应以重建和独立核验证明为主，不强制安排数据集、基线或消融实验。

本轮的可交付结果是上述复现准备清单与待核命题；完整复现仍需要正文中准确的更新式和定理条件。请提供论文全文，或至少定义、主定理、算法和证明部分；现有一句摘要不足以确认唯一论文版本，不宜按标题猜一篇同名论文继续。

## K2：toy example 是否足以证明方法有效

### 题面

一篇论文中的 toy example 展示三步都得到正确输出。能否因此判定方法对真实任务有效，并跳过详细设计和实验？按课程说明读法。

### 实际加载依据

本补充题直接读取包内 `sources/L03-slides.md` 的 L03-P013/P014 及教师备注，并对照 `methods-and-evaluation.md` 的“先看 toy example，再回正文”。不是新增音频核听。

### 实际回答

不能由这三个成功步骤推出真实任务有效。这个例子首先帮助我们理解操作：输入是什么、三步如何传递信息、输出为何在这个设定下正确；它不是一般有效性的证明。

课程第3讲P014建议先找toy example快速理解，再读详细方法；同页教师备注明确提醒例子可能不完整或误导。因此读完要回正文核对：例子省略了哪些输入条件、规模和分支；真实算法是否还有阈值、优化或失败处理；哪些性质有证明，哪些结论需要实验。若真实任务与例子条件不同，要沿差异核查设计与证据，不能把“我能跟着例子算出结果”当作“我已经验证方法”。

本题只有例子成功这一事实，可以说它展示了一个受限条件下的工作过程；不能宣称普遍正确、真实效果已验证，也不能据此判论文无价值。下一步按用户目标补读设计与相应证明/实验，优先处理影响主张的缺口。

## K3：MobiCom四类标准是否需要同时满足

### 题面

有人据课程评价页要求一篇研究必须同时开辟新方向、提出新工具、实现核心领域技术飞跃，并完成可信评价的重要系统建设，否则不算好工作。该判断是否符合课件？

### 实际加载依据

直接读取包内 `sources/L03-slides.md` 的 L03-P041，与 `judgment-and-review.md` 的会场标准部分对照。这里核对的是所给课件，不声称已核验MobiCom当前正式评审规则。

### 实际回答

这个判断把课件中的选择关系改成了同时满足。L03-P041列出的四种贡献路径之间用“or”连接：开辟有吸引力的新方向；引入新的技术工具；在核心领域实现重要技术进展；或针对重要问题建设系统并给出有说服力的评价。它们帮助识别不同形式的贡献，不能变成四项全勾选的门槛。

评价具体工作时，先看它主张哪一种贡献、问题为何重要，再核查与该贡献相称的设计和证据。例如工作若主要贡献是可信实证的系统建设，就不应仅因没有另创新工具而否定；同样，声称新方向也不免除对其论证、相关研究和适用条件的检查。OR不表示只要作者给自己贴一个类别就成立。

这页是课程引用的评价视角，不是所有学科的通用硬规定；当任务涉及实际投稿时，应另查目标渠道当次正式标准。
