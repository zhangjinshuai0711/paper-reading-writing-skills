# 图表、公式、算法与表达：使信息真正可读

来源标记对应第六讲物理课件页。这里的要求服务于准确传达研究；实际投稿模板与领域规范优先。图形是否表达正确、排版是否可读以及研究是否可靠是三个不同判断，不能互相替代。

## 一、决定一张图是否值得存在

先写一句“读者看完这张图应理解什么”。如果没有明确答案，先别画。图可以呈现结构、流程、现象、机制或结果，应与正文互补、含义一致。图不是装饰，也不是把一整段原文塞进方框。【课程：L06-P059–P064】

- 结构图帮助定位组件与关系；应有明确输入、输出、边或连接语义，名称与正文一致。
- 流程图帮助理解步骤及分支；要区分先后、依赖、数据流和控制流，不让所有箭头看起来都代表同一关系。
- 结果图帮助比较趋势、分布和权衡；坐标、单位、图例、条件与指标方向必须可辨。
- 表格帮助查精确数值或离散属性；不要把表格变成读者难以追踪的数字墙。
- toy example 帮助理解机制；必须说明简化条件，不用“容易的例子成功”替代一般有效性证明。

【课程：L06-P059–P064、P086–P088；整理：按图的任务分类】

图表通常靠近首次引用位置，尽量让图与说明在相邻阅读范围。课件建议同页或后页、页/栏顶部等，是排版经验；不能为了满足位置而打乱模板或产生大片空白。正文先告诉读者为何看图，再解释最关键现象与意义，不逐项复读图中每一个数。【课程：L06-P063–P064、P070–P079】

## 二、自明性：把图从上下文拿出来仍可正确读

自明性不要求读者在一张图里重读整篇论文，而是让图的对象、编码、条件和结论范围清楚。

检查图名/图注、横纵轴与单位、刻度、图例、缩写、颜色/形状/线型、子图标号、样本或环境条件是否必要且齐备。缩写在正文定义过，仍须判断图注是否需要展开，以免读者来回翻页。只写 “Code example” 或 “Performance” 信息不足，应说明示例展示哪种机制、性能对应什么对象和条件。【课程：L06-P066】

图注采用中性且有信息的表达，例如“不同输入负载下各方法的第 95 百分位时延；误差线表示……”。若误差线、置信区间或标准差没有实际计算，不能为了规范外观补画；有误差线时必须说明含义。图中只观察到局部指标变化时，图注不写“全面证明系统优越”。【整理；课程 L06-P066、P045–P046】

架构图至少核对：模块职责是否清楚；箭头两端是否确实相连；每条重要边传递什么；离线训练与在线推理是否区分；可选部分与已实现部分是否易辨。使用颜色帮助分组，但不能仅凭颜色承载不可替代的意义。【整理；课程 L06-P028–P029、P066、P070–P079】

## 三、可读性以实际成稿尺寸为准

在最终 PDF 的正常阅读比例检查，而不只在画图软件放大状态检查。字体应与正文尺度协调，线条、点和标记不消失；最小文本不能被压到不可读。不同操作系统检查字体嵌入与替换，图中文字、数学符号和正文术语保持一致。【课程：L06-P070–P079】

图表优先选择适合内容的矢量格式，尤其曲线、示意结构和文字；真实照片或栅格内容使用足够清晰的图像，不把低清图片另存为 PDF 就声称变成高质量矢量。检查输出后有没有裁切、糊字、字体缺失、透明度变化或图例越界。【课程：L06-P070–P079；整理：导出核对】

打印/灰度检查能揭示只在屏幕颜色下可辨的编码。用线型、标记、直接标签或明暗辅助区分；避免红绿等一旦失去色彩就无法区分的组合。子图应有足够间隔、统一视觉约定，比较对象的坐标尺度尽量可比；尺度不同应明确标出，不能靠隐藏截断制造差距。【课程：L06-P070–P084；整理：编码与尺度检查】

工具选择取决于需要的功能、团队协作、跨平台输出和熟悉程度。课程不规定一个唯一正确的绘图软件。优先使用可编辑源文件与稳定导出流程，保留真实数据及生成代码（若有），以便修正图中文字和数值，而非反复截图。【课程：L06-P085；整理：可维护输出】

图的迭代不仅是美化：每一轮检验信息是否更容易识别，图例是否足够，是否有不必要视觉元素。L06-P080–P084 的真实内嵌图已恢复补核：v1 以黑白多种线纹/点纹堆叠，v2 放大标签并调整部分颜色/纹理，v3 混合彩色、粗边和多种纹理，v4 改为较简洁的实心色块，再检查其灰度版本。不同版本也有类别名称和合并方式变化，不能把它们当成严格相同数据的受控样式实验。可迁移的判断是减少辨码负担、保留必要信息、检查最终灰度可辨性；不是规定每幅图必须经历这四版。见 [恢复原图与课页](source-index.md)、[逐页核验](coverage.md)。

## 四、结果图表与正文的配合

每幅实验图写正文前，先在内部回答：实验问什么；数据怎样产生；图中直接出现什么；哪些机制能解释；还存在哪些替代解释；对中心主张有什么意义。正文按“设置—客观观察—解释与边界”展开。【课程：L06-P045–P046】

“图 4 显示 A 为 10、B 为 8”通常只复读数字；“在已测负载范围内，B 的时延比 A 低；高负载处差距扩大，提示排队开销可能是关键因素，需结合组件实验进一步检验”更接近分析。若没有组件证据，保留“可能”；若实际数据只测一个负载，不写“范围内”或“高负载”。【整理：教学句式，不是课程实验事实】

表格适合准确查值、方法属性与配置对照；图适合趋势和分布。无需把同一信息同时复制成图和表，除非两种阅读任务都重要。表格也要自含，给列含义、单位、符号、较优方向及必要条件。加粗/下划线的意义在图注或表注说明；“最佳”需限制在实际比较对象和条件中。【课程：L06-P086–P088；整理：比较范围】

任何图表修改后反查正文数值、摘要、结论与原数据。改变单位、归一化方式或百分比算法会改变含义，必须同步核对。外观通过不等于数据已验证。【整理】

遇到均值、百分比或“重复 N 次”，先核分母、样本/重复单位、各组次数和独立性；不把总 N 自动写成每组 N，不把同一轨迹重复运行当独立场景。绝对差、百分点与相对变化分别计算并说明基准；口径缺失时保持已知范围，把图注标为待核过程稿，不补造误差线或显著性。【整理：数值与计数口径，非课程逐字统计规范】

## 五、公式：让数学继续讲同一个故事

公式不是从正文中孤立出来的装饰。先说明它要表达什么、为何需要，再给定义与条件，随后说明如何使用及结论。变量在首次使用时解释；相同对象保持同一符号，不同对象不要复用同一字母造成歧义。符号很多时可加表，但不能只把符号表放远处而让正文难读。【课程：L06-P089–P094】

独立展示核心公式有助于阅读和引用；课件对此的偏好不能变成禁止所有行内变量的规则。短符号与必要简式可按版式放行内，较长公式、关键定义和需要引用的表达可独立编号。公式与句子共同组成语法，应有合适标点和连接说明。

数学表达至少核对：变量类型与取值域；下标与集合范围；函数输入输出；约束与优化目标；单位和维度（适用时）；等号/近似号/不等号的条件；分母、边界情况和默认假设。润色时不得无声改变这些内容。【整理；课程 L06-P089–P094】

系统、网络和安全论文常把冗长机械推导移到附录，但正文仍须保留决定读者理解与相信方法的核心方程、直觉、关键推理和条件。理论论文则要按其证明任务安排，不能把课程针对系统论文的压缩建议泛化为“数学越少越好”。【课程：L06-P092–P094；整理：领域适配】

若用户只给公式截图且无法可靠辨认，标明需要核对的符号，不能凭上下文编补。例子验证的是示例条件，不能代替一般证明。计算工具检查通过也不代表全部理论假设正确。【整理】

## 六、算法、伪代码与代码片段

先选择表示层次：真实代码便于说明具体接口或实现行为；伪代码便于解释算法逻辑。避免在同一段里混用真实语言与未说明的抽象操作，导致读者不知道哪些能执行、哪些需要另行定义。【课程：L06-P095–P097】

使用有意义的名字，不让 `foo`、`bar` 或单字母无解释地承担关键概念。交代输入、输出、状态、循环/停止条件、关键分支与必要注释；正文引用重要行时说明它为何解决挑战。去掉日志、导入与样板代码，保留不可省略的逻辑；没有充分材料时不杜撰完整算法。【课程：L06-P095–P097；整理：接口检查】

检查伪代码是否与公式、文字和实际实现一致，尤其初始化、阈值、边界、随机性、重试和失败处理。若算法省略了不影响主旨的细节，应明说省略范围；若省略会改变正确性，就必须补回。代码截图的可见外形不能证明算法本身正确。【整理】

## 七、语言：让读者少猜一层

### 用明确事实替换评价性形容词

课程强调客观、简洁、易懂。用“在数据集 D 上，相对基线 B 的指标 M 改善 x，代价为 y”替换“我们的伟大创新显著提升性能”。“显著”在统计意义、实际意义和普通修辞中不同；没有相应依据就用具体观察，不擅自赋予统计含义。【课程：L04-P018、P034–P036；L06-P102】

慎用 “clearly/easily/obviously/trivially”：它们既不增加证明，也可能令没看懂的读者受挫。若步骤真简单，给出理由或例子即可。“novel” 可用于精确对比新内容，但不能代替展示差异的工作。【课程：L06-P102】

### 句子和段落保持一个可追踪的任务

长句不必一律拆，但当条件、动作、转折与例外互相缠绕时，先梳理逻辑，再分句。课程飞机测试示例从一长句分成多句，关键是保留“测试不能覆盖每种真实紧急情境”的限制，不能为了简短删掉否定和条件。【课程：L06-P101】

主动语态常使行动主体更清楚；被动语态在主体不重要或强调对象时仍可使用。现在时适合表达论文内容和稳定陈述，过去时适合已做实验与过程；按句子的实际时间与语义决定，不能机械统一全篇时态。【课程：L06-P102、P104】

代词应有明确指向。含糊的 “This improves performance” 可改成 “This cache policy reduces repeated disk reads …”，但新增机制必须真实。therefore/however/because 应表达已经存在的因果或转折，不用连接词掩盖缺失前提。层级结构别只出现一个孤立的子子节；能合并则合并，确有并列关系再设置层级。【课程：L06-P103】

“previous work” 等词语偏好是课程写作建议，不是语法正确性的普遍规则。术语选择应准确、一致并符合领域。少用华丽词，不等于删掉必要限定、专业术语或证据强度。【课程：L06-P104；L05-P012】

### 保真润色的操作顺序

先锁定数字、单位、符号、引用、专有名词、逻辑连接、否定和范围词；再改句法与词语；最后逐项对照。若改动把 “may” 变成 “does”、把 “in our prototype” 删掉、把 “among the evaluated baselines” 改成 “all existing systems”，就是实质改变，不能当成纯润色。【整理；课程 L04-P018、L05-P044】

拼写与语法工具应实际运行并检查其建议。工具、服务或语言模型给出的修订不是自动正确，不能未经判断应用。课程列举润色服务不等于授权上传未公开论文；使用服务的范围按用户授权与任务实际条件决定。【课程：L06-P099–P100；整理：工具边界】

## 八、最终成稿检查

按论文真实输出检查一遍：正文引图与图号正确；图注中术语、单位、图例清楚；正常比例能读；黑白条件仍区分主要系列；公式符号和编号一致；算法引用无断裂；参考文献无缺项或占位符；摘要、正文与结论的结果一致；最终版没有草稿批注与待补标记冒充完成内容。

检查记录区分“已核对源数据”“已核对排版结构”“已渲染目视检查”“尚未验证”。若本轮只改 Markdown 文字，不声称最终 PDF 排版已通过。具体字体、字号、双栏宽度与浮动位置以最终模板和读者实际阅读环境为准。【整理；课程 L06-P070–P079、P099–P104】
