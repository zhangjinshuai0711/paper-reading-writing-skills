# 论文章节指南：每一节替读者完成什么

本指南依据第四至六讲。标记 `L06-P032` 指第六讲第 32 张课件；“整理”表示将教学原则变成操作检查。章节是否独立设置、长短和先后须服从论文类型、论证需要及实际投稿格式。课程示例以计算机、安全、网络和系统研究为主，不能把其所有习惯当成各学科统一规定。

## 0. 先按论文任务选择结构

研究论文通常包含问题、相关背景、核心方案、验证与结论，但不必机械设置所有标题。经验论文可能以真实系统与经验教训为主；测量论文以测量问题、方法、发现、解释和有效性边界为主；综述/SoK 以范围、收集方法、组织框架、比较和研究空白为主。没有新系统的论文不要虚构“实现”，没有攻击者的论文不要硬加“威胁模型”。【课程：L04-P021、P042；L05-P013–P015；整理：类型适配】

通用检查是每节都回答一个必要问题，读者在需要概念时已经见过它，在看技术细节前知道其意义。篇幅不是按章节平均分配；影响主结论的机制和证据优先，旁支移入讨论或附录。【课程：L04-P033、P036；L06-P031、P057】

## 1. 标题：让对的读者识别真实内容

**任务**：在少量词语中表达论文研究什么，以及最值得记住的区别。标题兼顾准确、可检索、可记忆与吸引力；不是用夸张代替具体信息。【课程：L05-P019】

**写法**：先列“对象/问题”“核心机制或独特性质”“适用限制”，再选最必要的组合。若系统名有助记忆，用“系统名：具体描述”；若名字挤掉关键信息，宁可简化名字。标题中的词必须能被正文解释并由证据支持。

课程排序例子的关键是允许有界误差/不完全有序的近似条件。`Linear-Time External Multipass Sorting with Approximation Guarantees`、`Approximate External Sort`、`Floosh: A Linear-Time Algorithm for Approximate External Sort` 展示了信息量、简短程度与记忆点的取舍，不是在证明一般精确排序出现线性时间突破。不能为简洁删掉改变技术含义的 “Approximate”。【课程：L05-P020】

**验收**：读者看标题能知道主题；搜索关键词合适；没有隐去必要限定；没有“revolutionary”“universal”或无依据的最优宣称。可提供两三个有明确取舍的候选，不生成一长串空洞口号。【整理】

## 2. 摘要：脱离正文也能成立的微型论文

**任务**：摘要常被单独索引或阅读，因此要给完整主线，说明问题、方法和关键结果，而不是只有背景和愿景。【课程：L05-P021–P023】

**可用顺序**：重要场景与具体问题 → 现有办法的关键缺口 → 本文想法和怎样实现 → 核心验证及结果 → 结论范围。每一步可以合并，不要求固定句数。约 150–200 英文词是课件的经验量级，实际按投稿要求与信息密度决定。

摘要中的机制应让读者理解“为什么大致可能有效”，不需要重现所有实现参数。“先知道核心思路、细节留正文”不等于故意写得似懂非懂。【课程：L05-P024–P026；L05 转写 01:04:49，自动转写未核听】

**写结果**：有真实可比结果时给最关键的具体量、条件和对象；不要只说“实验表明有效”。没有结果时可写诚实的提案摘要或草稿，用明确待补标记；不能把预期提升改成过去完成式。百分比需明确相对/绝对含义、分母和指标方向。

**反查**：摘要每项主张在正文有定位；没有引入正文不存在的新贡献；研究范围与数据一致；自含所需缩略语；主张强度不高于证据。【整理；课程 L04-P032、L05-P029、P044】

## 3. 引言：先讲清整篇，再让读者愿意读细节

**任务**：引言是真正开始讲故事的位置，让读者知道问题、价值、困难、核心想法与主要证据。不要把最关键想法藏成悬念，也不要写成从宏观背景到领域常识的长漏斗。【课程：L05-P027–P032】

先独立写一段总述，若写不清，检查研究问题或贡献是否尚未凝练。再把它拆成若干读者问题：

1. 研究发生在什么场景，具体要解决什么问题？
2. 为什么这个问题值得读者在意？
3. 为什么自然方案或最接近研究没有满足需要？
4. 本文提出什么核心想法，它怎样回应上述挑战？
5. 实现和证据说明了什么？
6. 真实贡献与适用边界是什么？

每个问题可由一段回答；首句先给答案，其余句子给理由、事实或例子。课件的七段安排与“约一至一页半”是常见论文的参考，不是普遍篇幅规则。抽读各段首句，应能还原整篇逻辑。【课程：L05-P028–P032、P048】

**重要性**用真实影响、使用需求、错误后果或可信背景来源说明。**困难**要给机制，例如两个目标冲突、已有方法依赖不满足的前提、现有数据不足以识别某状态。只列“复杂、动态、海量”没有解释困难。**方案**先核心洞见，再组件，不从零件清单开始。**证据**选最能回答主张的结果，不把所有表格压进引言。【课程：L05-P033–P042】

DeepAID 例子按“无监督异常检测为何难解释—已有解释办法在哪些机制与需求上不合适—怎样解释并帮助改进系统”组织。其具体目标、Interpreter/Distiller、数据类型和案例属于该研究，不是每篇论文都必须复制的模块。示例中关于深度学习全面超越其他方法等宽泛断言，也应按实际证据检查，不因出现在课件截取中就泛化采用。【课程：L05-P036–P043】

**贡献列表**可独立列出，也可并入方案总述，贡献已经明确时可省略。清楚、吸引人、真实是共同要求；典型三项或不超过五项是防止分散的经验，不能为凑数拆出虚假贡献。贡献不等于“本文共六章”，也不等于“我们使用了 Python”。原型、实验、数据集可构成贡献，但应说明带来什么新能力/证据，而不是仅列活动。【课程：L05-P043–P047】

避免“首次”“最先进”“显著”“开创性”的自我授勋；若确有范围明确的首创证据，写清范围及对照。课件某处“Be subjective”与客观表达原则存在张力，不解释成鼓励主观夸大，采用准确陈述供读者判断。【课程：L04-P018、L05-P044、L06-P102；整理：冲突消解】

## 4. 背景：只铺后文必需的台阶

**任务**：补足目标读者理解问题与方案所需的知识。自含意味着提供必要定义和解释，不意味着写一本入门教材。【课程：L04-P020、P036；L05-P050；L06-P005】

对每个背景概念问：“后文哪一步会用到？不讲会造成什么误解？”有明确答案才保留。定义本文使用的具体含义与条件；通用概念可简述并给来源，特别术语需说明。面向较广读者时增加必要台阶，领域专家常识不必长篇复述。

若背景太长，先检查是否混入了相关工作比较、方法设计或无关历史。不要因为某概念很有趣就写进来。长背景有时必要，不据此断定工作无创新；要看其是否服务主线并控制读者负担。【课程：L05-P050–P051；L06 转写 00:00–09:36，未核听】

**验收**：后文关键概念已有定义；每一段背景都被后文使用；未提前陷入低层实现细节；删除后不影响理解的内容已压缩。【整理】

## 5. 相关工作：按主题比较思想与边界

**任务**：让读者理解研究版图，准确介绍重要路线，定位本文与它们的关系。不是按作者年份逐项报名字，也不是专门挑弱点的广告段落。【课程：L05-P053–P059；L06-P009–P014】

至少从两条轴检索与组织：**相同/近似问题**的不同解法；**相同/近似方法**在其他问题上的运用。先分类，再选择每类代表工作；最接近的少数工作需更精确比较。比较维度可包括问题定义、输入信息、目标、假设、机制、输出、评估条件与代价。分类是帮助解释，不为了画满表格制造互斥类别。

可用段落骨架：“这一类工作通过 A 解决 B；代表工作……。其成立依赖 C/适合 D。本文关注 E，因此在 F 处采取 G；关于 H 的比较由第……节给出。”不能在未读原文或未核实情况下断言“所有现有工作都没有考虑”。

若只给 A/B/C 等机制名或零散笔记，可以交付暂定分类、比较维度与待核资料；不能补造题录、性能和缺点。原文与引用未核查时，明确这仍是组织草案，不能标为已完成文献核查的可提交综述。【整理：材料不足分支】

**位置选择**：若篇幅很短或读者必须先理解差异，可放前面；若比较依赖技术细节、且引言已经足够定位，可放后面。前后位置由可理解性决定，不把后置相关工作视作“作者自信/论文创新高”的证据。【课程：L05-P059；L06-P014】

**验收**：最接近路线未遗漏；描述公平；每条差异有原文或结果支撑；没有把不同数据、假设和任务的指标硬排高低；引用真的存在且指向正确。【整理；课程 L06-P056】

## 6. 动机与问题定义：把“值得做”说成可检验的问题

**任务**：用实际影响、经验观察或逻辑推导证明问题存在、重要、困难并尚未被满足，然后明确研究对象和目标。独立 Motivation 节是可选形式，引言已经充分完成则不重复。【课程：L05-P061–P066；L06-P016–P021；L06 转写 25:02 起，未核听】

现实例子负责说明“会发生什么”，测量负责说明“在所测条件下多常见、多严重”，逻辑负责说明“为什么现有机制导致问题”。三者可组合；没有经验数据也可进行严格逻辑论证，但不能把设想写成普遍事实。经验曲线不能自动证明提出的原因，需排除其他解释或收窄措辞。

问题定义说明输入、输出、成功标准、约束和研究范围。必要时使用符号，但应配一个具体例子帮助理解。定义过宽而验证过窄时，缩小问题或补验证；不要只在局限角落悄悄撤回总目标。【整理；课程 L06-P016–P026】

## 7. 威胁模型：仅在存在对抗主体时启用

**任务**：说明论文打算防什么、在何种条件下保证什么。列清攻击者、受害者和防御者的身份、目标、可观察信息、权限、能力、限制与交互关系；说明这些假设为何现实，哪些攻击不覆盖及原因。【课程：L05-P067、P069–P071；L06-P023–P026】

“攻击者无法做 X”需要依据，例如硬件信任根、权限边界或明确研究范围，不能仅因为 X 会打败方法就排除。成本、收益与实际行为可支持特定对手假设，但不是所有攻击者都追求同一种经济效益。定义边界后检查实验与安全主张是否一致：较弱对手下有效，不支持抵抗任意对手。

必要时同时给形式化表达与具体攻击过程，使读者知道能力如何影响机制。一般预测、优化、材料或医学研究不强行加入攻击者；可以按其任务采用假设、适用人群、测量误差或有效性边界说明。【整理：跨领域对应】

## 8. 概览：先交付技术地图

**任务**：让读者在进入细节前知道目标和约束、设计原则、核心直觉、组成部分及其关系。它比引言更技术化，比详细设计更概括。可以独立成节，也可以放在设计章开头。【课程：L06-P027–P029】

推荐顺序：设计目标和约束 → 从约束推导的原则 → 为什么核心想法可能有效 → 架构图与组件职责 → 后文章节路线。图中说明输入、输出、数据流/控制流和关键交互，正文解释每块的作用与必要性。不要把“有 A、B、C 三模块”当作已经解释方法。

课程用十二页论文约第三页前后应见技术贡献说明，提醒不要让背景挡住新内容；它不是每种版式都必须在全篇四分之一处出现某节的硬性规则。【课程：L06-P027】

**验收**：不看细节也能复述主流程；各组件名称与详细设计一致；每个组件知道“为谁解决什么”；核心直觉没有替代理论或实验，只预告后续证明。【整理】

## 9. 详细设计：把每个组件写成一个小论证

**任务**：提供可理解、可检查、必要时可复现的核心技术内容。章节随技术主题安排，不强行统一目录。【课程：L06-P030–P033】

每个重要组件依次考虑：

1. 本组件目标及在全局中的作用。
2. 核心思路，以及选择它的理由。
3. 达成目标的具体挑战。
4. 完整处理步骤、接口、算法/模型、假设和参数。
5. 正确性、复杂度、稳定性、安全性或其他与目标对应的分析。
6. 必要的边界与与其他组件的交互。

不是每项都必须独立小标题；关键是读者能找到答案。解释数学工具为何适合此问题，再进入推导；不能把全部关键数学放附录，正文只留下“通过优化即可”。对难点使用最小真实或明确简化的 toy example，并说明简化了什么，避免例子改变技术前提。【课程：L06-P032–P033、P089–P094；整理：例子边界】

设计章节名称、模块名和概览路线一致；不相关但有价值的细节放讨论。若某机制只是一种可能选择，不把它写成已实现事实。【课程：L06-P031、P034】

## 10. 实现：说明设计怎样落地，以及落地时改变了什么

**任务**：从概念设计过渡到实际系统/原型，说明平台、模块、接口、工程挑战、折中、兼容性和实际规模。理论方案、实现和 proof-of-concept 是不同层次。【课程：L06-P034–P036】

建立“设计组件 → 已实现模块 → 关键偏差 → 原因 → 影响”的对应。设计为了方便假设完整状态，而原型只获得采样状态，则必须写明，并说明误差如何影响结果。模拟器、原型、真实部署分别准确命名；使用真实流量回放不自动等于在线生产部署。

一般不贴长代码清单。保留理解结果和复现所需的版本、软硬件、配置、数据处理、参数及公开信息；未开源就不能写“代码已公开”。是否需要独立实现章依任务而定，理论论文可没有此章。【课程：L04-P019；L06-P034–P036、P041】

## 11. 评估：先讲条件，再讲结果及其意义

**任务**：验证核心设计是否达到目标，同时揭示边界、意外现象和新问题。精心挑出好看的实验不是研究质量的替代品。【课程：L06-P037–P046】

### 总体设置

- **数据**：来源、真实性、代表性、规模、是否足够支撑目标、采集/筛选过程、伦理与公开限制。
- **环境与实现层次**：实际系统、原型还是仿真，软硬件、组成模块、运行规模、设计对应和复现材料。
- **过程与参数**：步骤、划分、重复和不确定性处理（按研究需要），参数是什么、为什么这样取、如何确定。
- **比较对象**：为什么选这些基线，实际怎样配置与公平运行，是否遗漏合理强基线。
- **指标**：定义、计算、方向、为何对应目标，是否遗漏重要成本或风险。

【课程：L06-P039–P043；补充：重复/不确定性按任务需要属于可复现整理，非课件统一统计规范】

### 按证据问题组织结果

先总体端到端效果，再按主张安排组件分析、微基准/消融、参数与边界、实际案例和必要补充。顺序按研究逻辑变化；消融的目的在于验证具体设计作用，不是为了凑一个常规章节。【课程：L06-P039】

每个实验写三个层次：**如何做**（本实验特有设置与目的）→ **看到什么**（图表直接支持的客观现象）→ **意味着什么**（原因分析、目标是否满足、实际重要性、约束和新问题）。不要把相关现象直接写成因果证明；推测用“可能/与……一致”，有对照干预或理论依据时再强化。【课程：L06-P045–P046；L06 转写 01:13:41–01:16:50，未核听；整理：因果强度】

“提升十倍”只有在知道比较对象、条件和指标后才有意义。重点结果展开解释，次要结果简洁呈现。失败和意外结果不是自动删除对象：它们可能改变方法适用范围或启发后续研究。【课程：L06-P037–P046；L06 转写 01:09:53–01:16:50，未核听】

## 12. 讨论、局限与未来工作

讨论承接与主线有关但非核心的广泛问题、部署因素或解释；不拿它收容正文关键推理。局限应明确是什么、影响何种主张、为什么当前范围仍有价值；若局限直接推翻核心结论，就应修方法或缩小主张，不能靠修辞变小。【课程：L06-P047–P050】

解释可接受性必须给依据：影响在所测情境中有限、超出明确研究目标、或者由可检查的外部约束造成。不能把“未来硬件会解决”当成既成事实，也不能把重大缺陷说成“过于追求完美”。【课程：L06-P049–P050；L06 转写 01:18:23–01:23:43，未核听】

未来工作提出值得继续研究的问题与可行方向，最好来自已识别边界或新发现。若已有初步工作，仅在真实材料支持时描述；没有结果时不为“占领方向”虚构进展。它可以是独立短节，也可以并入讨论或结论。【课程：L06-P051】

## 13. 结论、致谢、参考文献与附录

**结论**简练回顾问题、核心想法和已经支持的结果，可进一步指出思想的意义、可迁移方向或未来问题。扩展价值使用条件化语言，不能在结论突然升级贡献或引入未经展示的结果。【课程：L06-P052–P053】

**致谢**感谢真实帮助与资助，核对姓名、项目号和贡献。署名与致谢边界遵循实际贡献和目标机构规范；匿名阶段按实际投稿要求隐藏，不能套用单一规则。【课程：L06-P054；整理：适用规范】

**参考文献**使用一致完整的题录，核对作者、标题、年份、出处和标识；题录存在还不等于支持所引论点。生成工具可能拼接不同论文信息，最终应逐条核实；未核验条目明确标记，不将看似完整的 BibTeX 当作真实性证明。【课程：L06-P056；L06 转写 01:27:30–01:28:59，未核听】

**附录**容纳补充推导、实现细节、实验与案例。正文必须独立支撑主要贡献与结论，不能假定评审一定阅读附录。具体投稿对附录是否纳入评审的规则以当次原文为准，课程提醒不替代实际政策。【课程：L06-P057】

投稿信、审稿回复、rebuttal、camera-ready 在课件中只作为后续文书提及，未构成完整教学模块。此技能可按一般事实约束协助，但不得声称已经从本课程蒸馏出完整的个人回复策略。【课程：L06-P058、P098；整理：覆盖边界】
